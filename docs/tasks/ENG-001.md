## 场景与目标

运维需要启动可配置的Go服务、识别进程是否存活，并在退出时释放端口。后续数据库与API在同一启动/路由边界增量接入。任务交付必须能够独立编译、启动、退出，不用假JSON宣称数据库就绪。

## 实现范围与接口

下列契约按任务推进实施；如需改变功能/主要逻辑先在Issue说明理由。文件组织允许按ADR-0002优化：
- go.mod：module github.com/yz1qaq/asterflow，Go 1.26.6，依赖按固定基线锁定。
- internal/config/config.go：type Config struct { HTTPAddr string }；Load() (Config, error)，读取ASTERFLOW_HTTP_ADDR，默认:18090（避免与已有本地服务混用），变量未设置用默认，显式空白拒绝；使用host:port语法且端口1–65535，不做DNS联网解析，不读密钥或连接数据库。
- internal/api/router.go：NewRouter() http.Handler，使用Gin v1.12.0，HandleMethodNotAllowed=true、RedirectTrailingSlash=false，注册GET /healthz返回200、Content-Type为text/plain和纯文本ok；POST /healthz为405，未知路径404。
- cmd/server/run.go：run(ctx context.Context, handler http.Handler, addr string) error；nil handler拒绝、监听失败返回错误，ctx取消后最多5秒Shutdown；成功返回nil，超时用Close兜底并等待Serve退出、返回包装后的Shutdown错误；正常http.ErrServerClosed不作为失败，不遗留run自身启动的Serve goroutine/监听端口。业务Handler需配合请求context取消，WS/hijacked连接的关闭由后续渠道任务负责。
- cmd/server/main.go：main()只负责错误日志/非零退出，start() error负责装配配置/路由、signal.NotifyContext和defer stop，再调用run；start清理返回后main才os.Exit，不把业务规则塞入口。
- 对应*_test.go由助手按功能归组编写；本轮没有Web页面需求，前端状态页在依赖就绪任务中接。
