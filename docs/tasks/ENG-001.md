# ENG-001：配置与HTTP基础服务

状态：Blocked，等待需求/架构PR确认。关联FR-18、MOD-CORE、EP-01。后端负责人：yz1qaq；助手承担测试/接口验收。本任务不是整个基础模块，也不提前实现IAM/模型/聊天。

## 场景与目标

运维需要启动可配置的Go服务、识别进程是否存活，并在退出时释放端口。后续数据库与API在同一启动/路由边界增量接入。任务交付必须能够独立编译、启动、退出，不用假JSON宣称数据库就绪。

## 可修改范围与候选接口

本任务进入Ready后冻结下列契约；如需变更先在Issue说明理由：
- go.mod：module github.com/yz1qaq/asterflow，Go 1.26.6，依赖按固定基线锁定。
- internal/config/config.go：type Config struct { HTTPAddr string }；Load() (Config, error)，读取ASTERFLOW_HTTP_ADDR，默认:18090（避免与已有本地服务混用），变量未设置用默认，显式空白拒绝；使用host:port语法且端口1–65535，不做DNS联网解析，不读密钥或连接数据库。
- internal/api/router.go：NewRouter() http.Handler，使用chi，注册GET /healthz返回200、Content-Type为text/plain和纯文本ok；POST /healthz为405，未知路径404。
- cmd/server/run.go：run(ctx context.Context, handler http.Handler, addr string) error；nil handler拒绝、监听失败返回错误，ctx取消后最多5秒Shutdown；成功返回nil，超时用Close兜底并等待Serve退出、返回包装后的Shutdown错误；正常http.ErrServerClosed不作为失败，不遗留goroutine/监听端口。
- cmd/server/main.go：装配配置/路由、signal.NotifyContext、错误日志/退出；不把业务规则塞入口。
- 对应*_test.go由助手按功能归组编写；本轮没有Web页面需求，前端状态页在依赖就绪任务中接。
