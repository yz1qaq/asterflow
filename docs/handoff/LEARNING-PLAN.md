# 10 天学习安排与完成条件

每天约 3–4 小时。学员要求完整 Final 交付；10 天是有明确停点的学习计划，不是 19 个需求组在 30–40 小时内全部手写、联调和合并的承诺。未达验收点可顺延；复用已验证组件并合并相关小步，不删功能。正式组顺序与依赖见 [路线图](../delivery/ROADMAP.md)，工作区当前标记见 [STATE](STATE.md)。

| 天 | 目标 | 收尾证据 |
| --- | --- | --- |
| 1 | G04 Prompt 核心 | 保存、追加、切换版本预览；缺变量、刷新回读和 dev 指针独立。G04 后续发布、diff、回滚、实验/灰度、Redis 的完整验收仍须完成。 |
| 2 | G05 Agent 与会话 | Agent/版本/快照与历史；旧会话不漂移，同一会话并发只有一个请求拿到租约。 |
| 3 | G06 聊天 | Gateway、主备、ADK、SSE、取消和持久化；网页聊天并核对历史。 |
| 4 | G07 业务工具 | 从 Agent 经已授权工具读取独立电商 PG，工具事件和消息刷新后保留。 |
| 5 | G08–G09 沙箱、MCP、A2A | 独立沙箱容器和真实协议试跑，验证超时与清理。 |
| 6 | G10 知识库 | 从来源到 Job、Worker、Chunk、Embedding、混合检索，再回读片段来源与权限边界。 |
| 7 | G11–G12 Skills 与审批 | 渐进加载、权限收窄；敏感工具批准前零执行，拒绝无副作用，恢复重放不重复。 |
| 8 | G13–G15 Team、Guard、额度 | 两种 Team 模式、Guard 拒绝、额度拒绝；说明 G03 静态配置如何转为运行时预留/结算。 |
| 9 | G16–G18 审计、观测与评估 | 追踪一轮请求的审计、模型和工具记录；错误样例触发评估门禁。 |
| 10 | G19–G22 渠道、SDK、业务场景与部署 | 本地渠道/CLI 测试、电商与保险场景、Compose 和新环境启动顺序；真实外部验收按组另记。 |

进度的单位分开：带学一批、学习一天、完成一个需求组和 GitHub 合并不是同一件事。每天要达到当日验收证据才对学员说「第 X 天任务完成」；每组要等正式代码、测试、适用桌面联调、CI、评审与人工合并才更新正式交付。重点解释每次改动如何连接数据库、Store、Service、Handler、运行时和界面，不能只给大段代码。
