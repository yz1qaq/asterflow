# Ready与Done标准

## Ready：任务可以开工

- 有FR/MOD/Epic关联、目标场景、明确范围/负责人/依赖。
- 请求/响应/事件、数据约束、权限、错误/重试/取消语义有约定。
- 可改文件/新增文件和验证方式清楚；涉及UI时前端与测试责任已分配。
- 需求/架构问题已评审；有新增决策就更新ADR。
- 每轮任务量与当前投入匹配，复杂项可以拆分，不删验收条件。

## Done：功能可以交付

- 生产代码实际保存，代码与任务/设计一致；无占位实现冒充完成。
- 相关编译/行为测试、必要race/vet、sqlc生成验证通过。
- 持久化/并发用隔离真实PG验证；上下文取消、权限/空间/非法输入/失败分支被覆盖。
- 可Web操作的功能完成实际桌面联调：正常/错误/加载/权限、切空间/会话、刷新回读。
- 受控模型/协议夹具、真实Docker、真实外部服务与质量分别标注；未验证项说明。
- 新配置/迁移/依赖/启动/回滚、接口文档、README/架构与模块状态已更新。
- PR写明触发场景、改动、验证、风险；CI通过，阻断评审问题修复并复审，未解决风险有负责人决定。
- 通过PR合并且按本次任务范围部署验证；不能只凭本地commit说已进入main或已上线。

## 文档/协作PR的Done

检查文档链接、FR/MOD/参考范围映射、结构化JSON、hook/工作流；独立审查需求缺口与错误承诺。此类PR无需伪造Go/数据库/浏览器测试通过；缺少业务源码的CI不执行空Go测试冒充门禁。

## 完整产品交付

FR-01至FR-18全覆盖；源文件/接口/页面/迁移语义有实现归属和证据；完整电商/保险场景、部署/重启/故障与质量检查通过。上游演进项和外部待验收内容分别列示，不靠模块目录数量宣布完成。
